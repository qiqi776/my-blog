### 链路层概述

**链路层**（Link Layer）负责在相邻节点之间（同一链路上）可靠地传输数据帧，是 TCP/IP 协议栈的最底层

链路层的主要职责：
- 将网络层的 IP 数据报封装成**帧**（Frame），加上首部和尾部
- 通过物理介质发送帧，并检测传输错误（CRC 校验）
- 管理对共享介质的访问（MAC，媒体访问控制）
- 将帧的 MAC 地址映射到 IP 地址（由 ARP 协助完成）

> **节点**在此语境下指主机和路由器；**链路**指相邻节点间的通信信道。一跳（hop）即一条链路

### 以太网与 IEEE 802.3

以太网是最广泛使用的有线局域网技术，现代以太网主要使用**Ethernet II**（DIX）帧格式

#### 帧格式对比

**Ethernet II（DIX）**：

```
 |  前导码   |  目的 MAC  |  源 MAC  | 类型(2B) |    数据(46-1500B)    |  FCS  |
 |  8 字节   |   6 字节   |  6 字节  |  EtherType  |  (含填充)       |  4 字节 |
```

**IEEE 802.3**：

```
 |  前导码   |  目的 MAC  |  源 MAC  | 长度(2B) |  LLC/SNAP  |    数据     |  FCS  |
```

区分方式：类型/长度字段 ≥ `0x0600`（1536）表示 Ethernet II 的 EtherType；< `0x0600` 表示 802.3 的帧长度

**常见 EtherType 值**：

| EtherType | 协议 |
|-----------|------|
| `0x0800` | IPv4 |
| `0x0806` | ARP |
| `0x86DD` | IPv6 |
| `0x8100` | IEEE 802.1Q VLAN 标签 |
| `0x8847` | MPLS 单播 |
| `0x88CC` | LLDP |

#### MAC 地址结构

MAC 地址（媒体访问控制地址）为 48 位，全球唯一地标识一个网络接口

```
 字节 0               字节 5
 ┌──────────────────────────────┐
 │  OUI (前 24 位)  │  NIC (后 24 位)  │
 └──────────────────────────────┘
  ↑ 第 1 字节最低两位:
    bit 0 (I/G): 0=单播, 1=组播/广播
    bit 1 (U/L): 0=全球管理(OUI), 1=本地管理
```

- **OUI**（Organizationally Unique Identifier）：由 IEEE 分配给厂商
- **广播地址**：`FF:FF:FF:FF:FF:FF`，所有接口都接收
- **本地管理地址**：随机生成或手工配置，U/L 位置 1；虚拟机网卡、容器 veth 通常使用此类地址

#### CSMA/CD（半双工以太网）

**CSMA/CD**（Carrier Sense Multiple Access with Collision Detection）是早期共享总线/集线器以太网的 MAC 机制：

1. **载波侦听**（CS）：发送前先监听信道，空闲才发送
2. **碰撞检测**（CD）：发送过程中同时监听，若检测到碰撞立即停止并发送**干扰信号**（jam signal）
3. **指数退避**：发生第 n 次碰撞后，随机等待 0 ~ 2ⁿ-1 个时隙再重试，最多 16 次后丢弃帧

> 全双工交换式以太网中不存在碰撞，CSMA/CD 实际上已无用武之地。现代网络几乎全部使用全双工交换机

### 全双工、自协商与流控

#### 双工模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 半双工 | 同一时刻只能发或收，需 CSMA/CD | 集线器环境（已淘汰）|
| 全双工 | 收发同时进行，无碰撞 | 现代交换机直连 |

#### 自动协商（Auto-negotiation，802.3u）

连接建立时双端交换 FLP（Fast Link Pulse）脉冲，协商速度（10/100/1000/10000 Mbps）和双工模式

> **强制设置陷阱**：若一端配置为强制全双工、另一端开启自协商，自协商一侧会因无法检测到 FLP 而回退到半双工，导致性能极差。两端应**同时**强制或**同时**自协商

#### 802.3x 流控（PAUSE 帧）

全双工链路上，接收方缓冲区将满时发送 **PAUSE 帧**（EtherType `0x8808`），要求对端暂停发送指定时长，防止帧丢失

### 网桥与交换机

#### 二层转发原理

交换机维护一张 **MAC 地址表**（CAM 表），记录 `MAC 地址 → 端口` 的映射：

1. **学习**：收到帧时，将源 MAC 与入端口记入表，并刷新老化计时器
2. **转发**：查表找到目的 MAC 对应端口，只转发到该端口（**单播转发**）
3. **泛洪**（Flooding）：目的 MAC 未知，或为广播/组播，则向除入端口外所有端口转发
4. **过滤**：目的 MAC 与源 MAC 在同一端口，丢弃（本地通信无需转发）

> 老化时间默认通常为 300 秒。MAC 表满后新条目无法学习，交换机对所有未知单播泛洪，退化为集线器行为

#### 生成树协议（STP，IEEE 802.1D）

多条上行链路带来冗余，同时也引入了**二层环路**（广播风暴、MAC 表震荡）。STP 通过选举使冗余端口进入阻塞状态消除环路：

1. 选举**根桥**（Root Bridge）：Bridge ID（优先级 + MAC）最小的交换机
2. 每台非根交换机选出**根端口**（Root Port）：到根桥路径开销最小的端口
3. 每段链路选出**指定端口**（Designated Port）：负责该链路上转发流量的端口
4. 其余端口进入**阻塞**（Blocking）状态

**RSTP**（IEEE 802.1w）：引入端口角色（Alternate/Backup）和快速收敛机制（Proposal/Agreement），收敛时间从 STP 的 30–50 秒缩短到 1–2 秒

### VLAN（IEEE 802.1Q）

**VLAN**（虚拟局域网）在物理交换网络上划分出多个逻辑广播域，实现**隔离**和**安全分区**

#### 802.1Q 标签

在 Ethernet 帧的源 MAC 之后插入 4 字节标签：

```
 | 目的 MAC | 源 MAC | TPID(0x8100) | TCI | EtherType | 数据 | FCS |
                      ←──── 4 字节 ───→
                      TPID: 标识这是 802.1Q 帧
                      TCI:  3 位 PCP(802.1p 优先级) + 1 位 DEI + 12 位 VLAN ID (0–4095)
```

- **VLAN ID 0**：保留，用于携带 802.1p 优先级但不属于任何 VLAN
- **VLAN ID 1**：默认 VLAN（通常）
- **VLAN ID 4095**：保留

#### 端口模式

| 模式 | 说明 |
|------|------|
| **Access 端口** | 连接终端设备，收发不带标签的帧，交换机内部加/去标签 |
| **Trunk 端口** | 连接交换机或路由器，帧携带 VLAN 标签，允许多个 VLAN 通过 |
| **Hybrid 端口** | 华为设备概念，可对不同 VLAN 灵活配置是否携带标签 |

### 无线局域网（IEEE 802.11）

#### 802.11 帧格式

802.11 帧分三大类：**管理帧**（关联/认证）、**控制帧**（ACK/RTS/CTS）、**数据帧**

数据帧中最多含 **4 个 MAC 地址**字段（分布式系统中源/目的/BSSID/发射端）

#### CSMA/CA（载波侦听多路访问/碰撞避免）

无线信道无法边发边收，无法做碰撞检测（CD），改为**碰撞避免**（CA）：

1. 信道空闲 DIFS 时间后，等待随机退避时隙
2. 退避计数减到 0，开始发送
3. 接收方成功收到后回复 **ACK**；超时无 ACK 则重传

**RTS/CTS 握手**（可选）：发送大帧前先发 RTS（Request to Send），收到 CTS 后才发数据，解决**隐藏节点**问题

#### 基础设施模式 vs Ad Hoc

| 模式 | 拓扑 | 说明 |
|------|------|------|
| 基础设施（Infrastructure）| 终端 → AP → 有线网 | 最常见，家庭/企业 Wi-Fi |
| Ad Hoc（IBSS）| 终端直连终端 | 无 AP，点对点或小组网络 |
| Wi-Fi Direct（P2P）| 一端充当软 AP | 手机投屏、打印机直连等场景 |

### PPP（点对点协议）

PPP（Point-to-Point Protocol，RFC 1661）用于点对点链路（拨号、DSL、WAN 专线），提供认证、压缩和多协议支持

#### 帧格式

```
 | Flag(0x7E) | Addr(0xFF) | Ctrl(0x03) | Protocol(2B) | 信息字段 | FCS | Flag(0x7E) |
```

- **Protocol 字段**：标识载荷类型，如 `0x0021`=IPv4，`0x0057`=IPv6，`0xC021`=LCP

#### 协商子协议

- **LCP**（Link Control Protocol）：建立、配置、测试链路，协商 MRU、认证方式（PAP/CHAP）等选项
- **NCP**（Network Control Protocol）：为每种网络层协议单独协商，如 IPCP 协商 IPv4 地址

#### PPPoE（PPP over Ethernet，RFC 2516）

宽带接入中广泛使用，将 PPP 帧封装在以太网帧内，分两阶段：

1. **发现阶段**：客户端广播 PADI，ISP 侧服务器回复 PADO，协商建立会话（SESSION_ID）
2. **会话阶段**：PPP 帧使用 EtherType `0x8864`，承载在以太网之上

> PPPoE 引入额外的封装开销（8 字节），使有效 MTU 从 1500 降至 1492。若未正确配置 TCP MSS Clamping，大包可能被丢弃

### 环回接口（Loopback）

环回接口是纯软件的虚拟接口，数据不经过任何物理介质，由操作系统内核直接回送：

- IPv4：`127.0.0.0/8`，最常用 `127.0.0.1`
- IPv6：`::1/128`
- 用途：本机进程间通信、服务绑定测试、路由协议 Router-ID 稳定锚点

> 发往环回地址的包**不离开主机**，链路层驱动也不会发送。到达 IP 层后直接由内核本地投递

### MTU 与路径 MTU

**MTU**（Maximum Transmission Unit）是链路层单帧最大有效载荷字节数，超出需分片

#### 各链路层 MTU

| 链路类型 | MTU (字节) |
|---------|-----------|
| 以太网（标准）| 1500 |
| 以太网（Jumbo Frame）| 9000（需设备支持）|
| PPPoE | 1492（以太网 1500 - 8 字节 PPPoE 头）|
| IEEE 802.11（Wi-Fi）| 2304（但通常以 1500 与以太网对齐）|
| 环回接口 | 65535（Linux 默认）|
| IPv6 最低要求 | 1280 |

#### 路径 MTU 发现（PMTUD，RFC 1191/8201）

端到端路径上各段 MTU 可能不同，**路径 MTU**（Path MTU）是路径上的最小 MTU

**IPv4 PMTUD 流程**：
1. 发送方将 IP 头 **DF（Don't Fragment）位置 1**
2. 若中间路由器因 MTU 限制无法转发，返回 ICMP **类型 3 代码 4**（需要分片但 DF 置位）消息，并附带下一跳 MTU
3. 发送方降低发送的数据报大小，重传

**IPv6 PMTUD**：IPv6 路由器不做分片，只有源端才能分片，因此 PMTUD 是强制要求而非可选

> **PMTUD 黑洞**：网络中部分防火墙屏蔽了所有 ICMP，导致 ICMP 不可达消息被丢弃，发送方得不到 MTU 反馈，大包静默丢失。解决方案：在边界设备上配置 **TCP MSS Clamping**（将 SYN 包中的 MSS 强制改写为合适值）

### 隧道基础

**隧道**（Tunnel）将一种协议的数据报封装在另一种协议中传输，跨越不兼容或不互通的网络段

```
原始数据报:  [IP 头 A][TCP][数据]
隧道封装后: [外层 IP 头 B][封装头][IP 头 A][TCP][数据]
```

常见隧道类型：

| 隧道协议 | 封装方式 | 用途 |
|---------|---------|------|
| IP-in-IP（RFC 2003）| IPv4 in IPv4 | 简单 IP 隧道 |
| GRE（RFC 2784）| 任意协议 in IP | VPN、overlay 网络 |
| 6in4（RFC 4213）| IPv6 in IPv4 | IPv6 过渡，穿越 IPv4 网络 |
| 6to4（RFC 3056）| IPv6 in IPv4 | 自动隧道（已不推荐）|
| Teredo（RFC 4380）| IPv6 in UDP/IPv4 | 穿越 NAT 的 IPv6 隧道 |
| VXLAN（RFC 7348）| 以太帧 in UDP/IP | 数据中心 overlay 网络 |

> 隧道会减小有效 MTU（封装头占用字节），引入额外延迟，且外层 IP 头的 TTL 独立计算，调试时需注意区分内外层地址
