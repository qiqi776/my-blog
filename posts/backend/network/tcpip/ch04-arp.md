### 为什么需要地址解析

IP 地址是逻辑地址，以太网传输依赖的是 48 位 **MAC 地址**。当主机要向同一链路上的 IP 地址发送数据时，必须先知道对方的 MAC 地址——这一转换由 **ARP**（Address Resolution Protocol，RFC 826）完成

> ARP 工作在网络层与链路层之间，严格来说不属于任何一层，EtherType 为 `0x0806`

**工作范围**：ARP 仅限于**同一链路**（同一广播域）。跨路由器通信时，主机查 ARP 得到的是**默认网关**的 MAC，而非远端主机的 MAC

### ARP 报文格式

ARP over Ethernet/IPv4 固定 **28 字节**，字段含义通用（支持任意硬件类型和协议类型）：

```
偏移(B)  长度   字段缩写   字段名              以太网/IPv4 典型值
───────  ────   ────────   ─────────────────   ──────────────────────
  0       2     HTYPE      硬件类型             0x0001（Ethernet）
  2       2     PTYPE      协议类型             0x0800（IPv4）
  4       1     HLEN       硬件地址长度         0x06（MAC = 6 字节）
  5       1     PLEN       协议地址长度         0x04（IPv4 = 4 字节）
  6       2     OPER       操作码               0x0001 请求 / 0x0002 应答
  8       6     SHA        发送方硬件地址       发送方 MAC
 14       4     SPA        发送方协议地址       发送方 IP
 18       6     THA        目标硬件地址         请求时全 0；应答时填目标 MAC
 24       4     TPA        目标协议地址         目标 IP
```

#### 具体报文示例

**环境**：
- 主机 A：MAC `aa:bb:cc:11:22:33`，IP `192.168.1.10`（`= c0:a8:01:0a`）
- 主机 B：MAC `dd:ee:ff:44:55:66`，IP `192.168.1.20`（`= c0:a8:01:14`）

**ARP Request（A → 广播，询问 B 的 MAC）**

```
─── 以太网帧头（14 字节）──────────────────────────────────
目的 MAC : ff ff ff ff ff ff          ← 广播
源  MAC  : aa bb cc 11 22 33          ← A 的 MAC
EtherType: 08 06                      ← ARP

─── ARP 载荷（28 字节）────────────────────────────────────
偏移  字段   十六进制值                说明
00    HTYPE  00 01
02    PTYPE  08 00
04    HLEN   06
05    PLEN   04
06    OPER   00 01                     ← Request
08    SHA    aa bb cc 11 22 33         ← A 的 MAC
14    SPA    c0 a8 01 0a               ← 192.168.1.10
18    THA    00 00 00 00 00 00         ← 未知，全 0
24    TPA    c0 a8 01 14               ← 192.168.1.20（查询目标）

─── 以太网填充（22 字节 0x00）─────────────────────────────
（总帧长 42 字节，不足最小帧长 64 字节，补零至 60 字节有效载荷）
```

**ARP Reply（B → A 单播，告知自己的 MAC）**

```
─── 以太网帧头（14 字节）──────────────────────────────────
目的 MAC : aa bb cc 11 22 33          ← 直接单播回 A
源  MAC  : dd ee ff 44 55 66          ← B 的 MAC
EtherType: 08 06

─── ARP 载荷（28 字节）────────────────────────────────────
偏移  字段   十六进制值                说明
00    HTYPE  00 01
02    PTYPE  08 00
04    HLEN   06
05    PLEN   04
06    OPER   00 02                     ← Reply（唯一改变的固定字段）
08    SHA    dd ee ff 44 55 66         ← B 的 MAC（关键答案）
14    SPA    c0 a8 01 14               ← 192.168.1.20
18    THA    aa bb cc 11 22 33         ← A 的 MAC
24    TPA    c0 a8 01 0a               ← 192.168.1.10
```

> **帧长说明**：以太网最小有效载荷 46 字节（总帧 64 字节，不含前导码和 FCS）。ARP 载荷只有 28 字节，驱动层自动在后面**填充 18 字节零**凑满最小长度，接收方按 HLEN/PLEN 解析，忽略填充

### ARP 请求与应答过程

**场景**：主机 A（192.168.1.1）向主机 B（192.168.1.2）发送 IP 数据报，但不知道 B 的 MAC

```
A                         链路（广播域）                       B
│                                                             │
│──── ARP Request（广播） ──────────────────────────────────→ │
│  以太网目的: FF:FF:FF:FF:FF:FF                               │
│  "谁是 192.168.1.2？请告诉 192.168.1.1（AA:BB:CC:...）"      │
│                                                             │
│ ←──── ARP Reply（单播） ─────────────────────────────────── │
│  以太网目的: AA:BB:CC:...（A 的 MAC）                        │
│  "192.168.1.2 在这里，我的 MAC 是 DD:EE:FF:..."              │
│                                                             │
│  A 将 B 的 IP→MAC 映射写入 ARP 缓存                          │
│  后续直接封装帧发送，无需再 ARP                               │
```

**关键细节**：
- 链路上**所有主机**都收到 ARP 请求，但只有 IP 匹配的主机回复
- 收到 ARP 请求时，各主机会顺便将**发送方的 IP/MAC** 更新到自己的缓存（即使不是目标）
- 若目标 IP 在**不同子网**，主机对默认网关发 ARP，由网关负责后续转发

### ARP 缓存

ARP 缓存（ARP Cache / ARP Table）存储最近解析的 IP→MAC 映射，避免重复广播

```bash
# Linux 查看 ARP 缓存
ip neigh show
# 或
arp -n

# 输出示例
192.168.1.1 dev eth0 lladdr aa:bb:cc:dd:ee:ff REACHABLE
192.168.1.3 dev eth0 lladdr 11:22:33:44:55:66 STALE
```

#### 缓存条目状态（Linux NUD 状态机）

| 状态 | 含义 |
|------|------|
| `REACHABLE` | 最近确认可达，直接使用 |
| `STALE` | 超出可达时间，下次使用前需确认 |
| `DELAY` | STALE 后发送了数据，等待确认 |
| `PROBE` | 发送单播探测，等待回复 |
| `FAILED` | 探测失败，条目无效 |
| `PERMANENT` | 静态配置，永不过期 |
| `NOARP` | 无需 ARP（如点对点接口）|

> Linux 默认 `REACHABLE` 时间约 30–60 秒，`STALE` 后条目保留但标记需验证。Windows 默认缓存时间 2 分钟，最大 10 分钟

### 免费 ARP（Gratuitous ARP）

**免费 ARP**（Gratuitous ARP）是主机**主动通告自身 IP/MAC 映射**的特殊 ARP，请求中目标 IP 与发送方 IP 相同：

```
发送方 IP = 目标 IP = 自己的 IP
发送方 MAC = 自己的 MAC
目标 MAC = 00:00:00:00:00:00（请求形式）或 FF:FF:FF:FF:FF:FF（应答形式）
```

**主要用途**：

1. **IP 冲突检测**：启动时或配置新 IP 后发送，若收到应答则说明 IP 已被占用
2. **缓存更新**：网卡更换/热备切换后，通知链路上所有主机更新缓存中对应的 MAC
3. **HA 故障切换**：VRRP/HSRP 主备切换时，新主设备发送免费 ARP 更新上游交换机和主机的缓存

> 操作系统在以下时机自动发送免费 ARP：接口启动、IP 地址配置/变更、从休眠唤醒

### 代理 ARP（Proxy ARP）

**代理 ARP** 由路由器代替不在同一链路的主机回复 ARP 请求，使发送方误以为目标在本地链路：

```
主机 A（192.168.1.10）
  ↓ ARP Request: 谁是 10.0.0.1？
路由器（同时连接两个网段）
  ↓ ARP Reply: 10.0.0.1 在这里，MAC 是我的 MAC（代答）
主机 A 将帧发给路由器，路由器转发到 10.0.0.1 所在网段
```

**使用场景**：
- 早期无子网掩码配置的主机（已过时）
- 某些移动网络/VPN 场景，终端不参与路由
- 可在路由器接口上用 `ip proxy-arp` 启用（Cisco），默认关闭

> 代理 ARP 会使主机看不到真实的网络拓扑，也增大 ARP 缓存规模。现代网络应避免依赖代理 ARP

### ARP 安全问题

#### ARP 欺骗（ARP Spoofing / ARP Poisoning）

ARP 无任何认证机制，攻击者可发送伪造的 ARP 应答，将自己的 MAC 与他人 IP 绑定，实施中间人攻击（MITM）：

```
正常: 主机 A 的 ARP 缓存  10.0.0.1 → 路由器 MAC
攻击后: 主机 A 的 ARP 缓存  10.0.0.1 → 攻击者 MAC
```

**防御措施**：
- **动态 ARP 检测（DAI）**：交换机检查 ARP 报文的 IP/MAC 是否与 DHCP Snooping 绑定表一致，不符则丢弃
- **静态 ARP 绑定**：手工绑定关键 IP/MAC，防止被覆盖
- **802.1X 端口认证**：限制接入设备，从源头减少攻击面

### IPv6 的地址解析：邻居发现协议（NDP）

IPv6 **完全不使用 ARP**，改用 **NDP**（Neighbor Discovery Protocol，RFC 4861），基于 ICMPv6 实现，功能更强大

#### NDP 的五种 ICMPv6 消息

| 类型 | 代码 | 消息名 | 缩写 | 用途 |
|------|------|--------|------|------|
| 133 | 0 | Router Solicitation | RS | 主机请求路由器发送 RA |
| 134 | 0 | Router Advertisement | RA | 路由器通告前缀、网关、标志 |
| 135 | 0 | Neighbor Solicitation | NS | 询问 IP 对应的 MAC（替代 ARP 请求）|
| 136 | 0 | Neighbor Advertisement | NA | 回应 NS 或主动通告 MAC（替代 ARP 应答）|
| 137 | 0 | Redirect | — | 路由器通知更优下一跳 |

#### 邻居请求与邻居公告（NS/NA）

NDP 用**被请求节点多播**替代 ARP 广播，显著降低广播开销：

```
A（2001:db8::1）想找 B（2001:db8::2）的 MAC

A → 被请求节点多播地址 ff02::1:ff00:0002（仅 B 订阅此组）
    NS: "谁有 2001:db8::2？"

B → A（单播）
    NA: "我有 2001:db8::2，MAC 是 xx:xx:xx:xx:xx:xx"
```

> **被请求节点多播地址**：`ff02::1:ff` + 目标单播地址的**后 24 位**。例如 `2001:db8::1:2345` 对应 `ff02::1:ff01:2345`

#### 路由器发现（RS/RA）

- 主机启动时发送 **RS**（目的地 `ff02::2`，所有路由器多播）请求路由器信息
- 路由器定期（默认 200 秒）主动发送 **RA**（目的地 `ff02::1`，所有节点多播），也可响应 RS 立即发送

**RA 携带的信息**：
- **前缀信息**：`fe80::/10` 之外的前缀，供 SLAAC 使用
- **M 标志**（Managed）：置 1 表示应使用有状态 DHCPv6 获取地址
- **O 标志**（Other）：置 1 表示应使用 DHCPv6 获取 DNS 等其他配置（但地址仍用 SLAAC）
- **默认路由器生命周期**：0 表示本路由器不作为默认网关

#### 重复地址检测（DAD）

主机在使用新配置的 IPv6 地址前，必须先验证该地址在链路上是否已被使用：

1. 将待验证地址设为**暂定状态**（Tentative），此时仅接收不发送
2. 发送 NS，**源地址填 `::`（未指定地址）**，目标为待验证地址的被请求节点多播
3. 等待 1 秒（`RetransTimer`）：
   - 若收到 NA 或 NS（他人也在 DAD 同一地址），则该地址**冲突**，标记为 Duplicate，需人工处理
   - 无响应则地址**可用**，进入 Preferred 状态

> 免费 ARP 在 IPv4 中做类似工作，但 DAD 是 IPv6 的**强制要求**，而非可选

#### NDP vs ARP 对比

| 特性 | ARP（IPv4）| NDP（IPv6）|
|------|-----------|-----------|
| 协议 | 独立（EtherType 0x0806）| ICMPv6（IP 协议号 58）|
| 请求方式 | 以太网广播 | 被请求节点多播（更精准）|
| 路由器发现 | 需要 ICMP Router Discovery 或 DHCP | 内建 RS/RA |
| 地址自动配置 | 无（需 DHCP）| SLAAC 内建 |
| 重复地址检测 | 免费 ARP（可选）| DAD（强制）|
| 重定向 | ICMP Redirect | NDP Redirect（更丰富）|
| 安全 | 无认证，易欺骗 | 可用 SEND（RFC 3971）加密签名 |
